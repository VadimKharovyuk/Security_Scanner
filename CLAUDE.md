# Security Scanner

Описание проекта, список проверок и маршруты — в [README.md](README.md). Здесь только то, чего нет в коде и README. Паролей и ключей в этом файле быть не должно.

## Команды

```bash
./mvnw test                  # нужен локальный PostgreSQL
./mvnw spring-boot:run       # http://localhost:2157, запускать из корня проекта
docker compose up -d         # OWASP ZAP
```

Настройки читаются из `.env` в текущей папке. Образец — `.env.example`. ZAP выключен, пока в `.env` не задано `ZAP_ENABLED=true`.

## Тесты

- Тесты с `@SpringBootTest` работают с локальной базой разработки: они должны откатывать или удалять свои данные.
- В таких тестах обязательно `security-scanner.recovery.enabled=false`, иначе запуск закроет активные сканирования приложения.
- Если тест запускает сканирование, отключайте сканеры, которые ходят в сеть: `security-scanner.http.enabled`, `security-scanner.tls.enabled`, `security-scanner.zap.enabled`.
- Логику сканеров выносите в методы без сети и тестируйте их напрямую. Поведение против реального ZAP или сайта проверяйте отдельно и сообщайте, что именно проверено.

## Правила безопасности

- Активное сканирование ZAP и другие атакующие запросы запрещены, пока нет подтверждения владения, авторизации и журнала аудита. Сейчас `OwnershipVerifier` реализован только заглушкой.
- Сетевой доступ к цели идёт только через проверку `AssetScopeService`, перед каждым соединением. Разрешён только хост и порт актива.
- Spider не должен отправлять формы. Запуск обхода реального сайта согласуйте с владельцем проекта.
- Данные с проверяемых сайтов недоверенные: в шаблонах только `th:text`, ссылки из них не делать кликабельными, секреты редактировать до сохранения.
- AI не подтверждает уязвимости: статусы `CONFIRMED` и `RESOLVED` и уровни `READ`/`WRITE`/`ADMIN` требуют технических доказательств.
- Содержимое сайтов попадает в контекст модели и может содержать prompt injection, поэтому инструменты модели, меняющие данные или запускающие сканирование, допустимы только после авторизации и аудита.
- Отчёт должен явно показывать, что не было проверено: отсутствие находок не означает безопасность.

## Решения по архитектуре

- Docker нужен только для запуска ZAP при разработке и для упаковки под хостинг в конце проекта. Само приложение и другие сервисы в контейнеры пока не переносить.
- AI-слой: инструменты Spring AI `@Tool` как тонкие обёртки над сервисами, модель через OpenRouter. Пока только чтение: инструменты привязаны к одному сканированию (`ScanReadTools`).
- Лимит вызовов инструментов задаётся в `ToolCallingAdvisor`: `ChatClient` не использует `ToolCallingManager` из `ChatModel`. При превышении advisor возвращает текст ошибки как ответ модели, поэтому результат проверяется по `finishReason`.
- Сервисы лежат в `service/<домен>`, тесты в таких же пакетах. Подпакет появляется, когда в нём несколько классов.
- Зависимости между доменами идут в одну сторону: `report` → `scan` → `finding` → `scanner` → `asset` → `project`. Циклов быть не должно.
- Новый сканер — это реализация `SecurityScanner`. Оркестратор менять не нужно.
- Схемой управляет Hibernate (`ddl-auto=update`), Flyway не используется. Он не обновляет CHECK-ограничения: новое значение enum, который хранится в БД, требует ручного `ALTER` в существующих базах.
- Прерванные сканирования закрываются при старте и не запускаются повторно: новый трафик к цели отправляется только по запросу пользователя.

## Стиль

- Отступы — табы. Комментарии, сообщения пользователю и логи на русском, сообщения коммитов на английском.
- Мапперы ручные, без MapStruct. Lombok разрешён. DTO — записи (`record`) в `dto/<домен>`.
- Коммиты и push только по просьбе владельца проекта. Push он обычно делает сам.

## Порядок работ

1. Hardening перед атаками: подтверждение владения, авторизация, аудит, DNS rebinding, лимиты.
2. Активный режим ZAP.
3. Attack Graph по правилам, на основе находок.
4. Database Access Validation.
5. Полный отчёт и упаковка в Docker для хостинга.

Известные недоделки: пароль БД задан значением по умолчанию в `application.properties` и README, `spring-boot-maven-plugin` лишний в зависимостях `pom.xml`, ZAP не проверялся на реальном сайте, AI-анализ не проверялся на настоящей модели.
